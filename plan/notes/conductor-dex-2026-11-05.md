# Turn orchestration lessons into verified improvement

Remudero should adopt **three narrow improvements: requirement coverage tied to the approved brief, bounded incremental task activity, and verified prerequisite outcomes in worker context**. Conductor shows how isolated agent work becomes easier to supervise and review; Dex shows how a small task interface can preserve intent and results between sessions. Neither inspected project establishes a new coding-model or autonomous-learning breakthrough. Remudero already implements many of their underlying mechanisms, including task dependencies, worktrees, continuation, shared dependency seeds, and reviewed improvement proposals. The strongest opportunity is therefore to connect its existing evidence more clearly from planning through execution and learning. This report distinguishes documented upstream behavior, current Remudero source findings, and proposed improvements; the new tasks are planning deliverables, not completed features or measured live benefits.

## Conductor makes agent work easier to supervise

**Meta's acquisition is confirmed by Conductor's own November 4 announcement.** The operational consequence matters as much as the transaction: Conductor Cloud becomes read-only November 13, shuts down November 20, and begins deleting data; the local product winds down in early 2027. Its export and cloud-to-local transfer options make portability an immediate concern. Remudero should learn from its design without creating a new dependency on the service. The announcement does not establish acquisition price, a future Meta architecture, or superior coding performance. ([Conductor announcement](https://www.conductor.build/announcement), [TechCrunch report](https://techcrunch.com/2026/11/04/meta-acquires-ai-coding-startup-conductor/))

Conductor's documented architecture organizes first-party coding agents, including Claude Code, Codex, Cursor, and OpenCode, around workspaces. A workspace provides its own branch, terminal, diff, and review context. Local workspaces use Git worktrees and begin from a freshly fetched remote base. This is a useful unit of delegation: one independently reviewable change can proceed without contaminating another change's working files. Worktree isolation is development isolation; the docs do not present it as a security boundary. ([Introduction](https://www.conductor.build/docs), [Workspaces and branches](https://www.conductor.build/docs/concepts/workspaces-and-branches))

The product's more distinctive value is the connected workflow. An operator can inspect the app, comment on a diff, send that feedback to an agent, examine checks and review threads, and finish the pull request in the same environment. Shared presence, followers, and reassignment separate visibility from responsibility. That distinction translates well to Remudero: observing a task should never imply owning its claim, and responsibility should remain explicit even when several people or agents can read the same work. ([Workflow](https://www.conductor.build/docs/concepts/workflow), [Multiplayer](https://www.conductor.build/docs/cloud/collaboration))

Programmatic supervision also contains a concrete reliability lesson. Conductor exposes transcript cursors and warns that an initial idle state can occur before the first message is delivered. A supervisor must observe actual work or a response before treating the agent as settled. Remudero should preserve its stronger operation and receipt semantics while adopting bounded incremental reads where current views are only clipped snapshots. **Liveness, idleness, task completion, verification, merge, and deployment must remain separate facts.** ([API](https://www.conductor.build/docs/api))

Its environment design separates a reusable successful build from repository setup performed for each workspace. Project configuration further separates setup, running actions, local overrides, and workspace ports. That separation is useful inspiration for diagnosing repeated setup friction, but it does not justify replacing Remudero's existing dependency seed system or automatically executing new repository hooks. ([Cloud Computer](https://www.conductor.build/docs/cloud/cloud-computer), [Project configuration](https://www.conductor.build/docs/configure-your-project))

## Dex preserves task intent more than autonomy

Dex at dex.rip is David Cramer's open-source task-memory CLI and agent skill, distributed as `@zeeg/dex`. It stores task descriptions, results, hierarchy, and blocker relationships, with optional integration metadata. Its appeal is a small, legible contract: find the current task, retrieve enough context to understand the work, and leave a useful result for the next session. The inspected repository snapshot was `3f55b2a3ec9746fc56cf62037ca6a828555ce17d`; the research reviewed source rather than installing or executing the package. ([Official site](https://dex.rip/), [Repository](https://github.com/dcramer/dex), [Task schema](https://raw.githubusercontent.com/dcramer/dex/main/src/types.ts))

The skill's instruction to retrieve the task, its parent, and completed blocker details is especially relevant. A dependency edge can explain when work is allowed to start without explaining what the dependency actually delivered. Supplying bounded, verified prerequisite outcomes gives a worker the information needed to use an earlier result correctly. That is a better adaptation than introducing a second task database or simply pasting all prior transcripts into every prompt. ([Dex skill](https://raw.githubusercontent.com/dcramer/dex/main/plugins/dex/skills/dex/SKILL.md))

Dex's plan command illustrates why implementation details matter. **The CLI creates one task containing the Markdown plan; intelligent decomposition lives in the agent skill.** The command itself does not compile a dependency graph. For Remudero, preserving the approved source is only half the problem: the planning path should also show which proposed task addresses each requirement, which requirements remain uncovered, and which apparent omissions were deliberately deferred. This requirement coverage receipt is an original recommendation inspired by Dex, not a capability attributed to it. ([Plan command](https://raw.githubusercontent.com/dcramer/dex/3f55b2a3ec9746fc56cf62037ca6a828555ce17d/src/cli/plan.ts), [Plan skill](https://raw.githubusercontent.com/dcramer/dex/main/plugins/dex/skills/dex-plan/SKILL.md))

Several Dex choices would weaken Remudero if copied literally. Blockers are advisory at completion, a result string does not establish test evidence, and local commit ancestry does not establish current hosted checks or deployment. JSONL storage writes by temporary-file replacement and rename, but the inspected read-modify-write path contains no visible lock or compare-and-swap transaction. Atomic replacement alone does not establish safe concurrent writers. These observations support retaining Remudero's canonical plan, claims, ledger, merge evidence, and explicit unknown states. ([Completion command](https://raw.githubusercontent.com/dcramer/dex/3f55b2a3ec9746fc56cf62037ca6a828555ce17d/src/cli/complete.ts), [Git predicate](https://raw.githubusercontent.com/dcramer/dex/main/src/core/git-utils.ts), [JSONL storage](https://raw.githubusercontent.com/dcramer/dex/main/src/core/storage/jsonl-storage.ts))

## Three missing contracts deserve focused work

The Remudero audit used current source rather than assuming the named checkout was current. Its initial local HEAD was twelve commits behind `origin/main`; the source comparison was therefore anchored to `1438f25d780f8119342dbc36dc8715f9c6670e26`. The audit found native mechanisms that should be extended rather than duplicated: product-plan operations already bind request identity, payload digest, frozen brief and head; worker continuation already distinguishes same-provider resume from a self-contained fresh handoff; dependency seeds already bind lock/configuration, platform, architecture, Node and ABI inputs. These existing foundations change the recommendation from buying or rebuilding an orchestrator to completing specific evidence connections. ([Native operation](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/src/lib/product-plan-operation.ts), [Worker continuation](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/src/lib/worker.ts), [Dependency seeds](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/src/lib/dependency-seeds.ts))

**W1-T11394 adds an operator-approved requirement-coverage observation.** The final proposed first slice adds an optional observational report to the existing product-plan operation response, with a source inventory and task/proof mappings when exact committed evidence is available. Explicit brief constraints and decisions receive source-bound pointers; free-form meaning remains nonexhaustive and unreviewed. Missing source, inventory or mapping stays unavailable/unmapped. The four-file scope is product-plan-operation, its existing integration suite, OpenAPI and the generated client. Product-case and product-build admission, proof verification, operation states and legacy validity stay unchanged. The native filing judge returned low risk with confidence 0.68, below the 0.70 proceed threshold, for both an earlier broader design and this narrower observation-only design. Both receipts are retained. The operator then explicitly approved the exact four-file scope in this chat on November 5, 2026. The canonical task is plan/tasks.d/W1-T11394-product-plan-requirement-coverage-receipt.yaml with a pinned operator proceed ruling. Both earlier model escalations remain retained; this is operator authorization to enter normal task filing, not a model confidence upgrade or implementation result. ([Native observation](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/src/lib/product-plan-operation.ts))

**W1-T11395 adds bounded cursor activity to the existing task read path.** Current task views expose clipped recent facts and tail lines, which make it difficult for a supervisor to distinguish newly arrived events from an incomplete snapshot. The proposed contract should return bounded incremental activity, stable ordering and explicit truncation or unavailable states. It should reuse the indexed activity ring and existing Workstreams cursor identities: decision facts do not contain every worker activity event, and a new raw-ledger scan would answer from the wrong population. Cursor size, retained demand-key cardinality and aggregate materialization work must also be bounded. A client should recover from an invalid or expired cursor without guessing that nothing happened. The endpoint remains observational; reading activity cannot launch work, release a claim, or satisfy completion. This is the transferable part of Conductor's supervisor experience, adapted to Remudero's durable evidence model. ([Task view](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/src/lib/task-view.ts), [Existing Workstreams activity](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/src/lib/workstreams-view.ts), [Query and view keys](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/src/lib/views.ts))

**W1-T11396 hydrates worker context with verified prerequisite outcomes.** The task DAG currently supplies dependency relationships, while the prompt path does not automatically provide the completed prerequisites' useful results. The proposed extension should retrieve a bounded outcome projection from authoritative task evidence, retain source and commit identity, and preserve missing, unreadable, stale or ambiguous states. It should link to further detail rather than copy unlimited history. A merged prerequisite establishes integration of its change; it cannot establish current behavior, downstream verification or production adoption. The existing prepared PR projection does not include merge commit SHA, so the first slice must report base applicability unknown where no verified commit is already captured. Both the actual recon and implementation preparation paths should receive these references, without per-dependency API calls, unbounded report injection or added authority. This extends Dex's retrieval discipline without replacing Remudero's continuation, task card, or case-file machinery. ([Prompt rendering](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/src/lib/prompt-render.ts), [Production preparation](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/src/cli/commands/run-task-verb.ts))

The recommended engineering sequence is W1-T11394 first, then W1-T11395 and W1-T11396 when the native selector, ownership and file-overlap admission allow them. This recommendation does not assert the current runnable frontier or bypass existing prerequisites. The native filing judge returned proceed for W1-T11395 at 0.78 confidence and W1-T11396 at 0.80; their exact pinned rulings are recorded. W1-T11394 carries the subsequent explicit operator proceed ruling, with the earlier escalations preserved. These three tasks form a coherent progression: **the planner accounts for the brief, the supervisor sees new evidence, and the worker receives the outcomes it depends on**. They should enter normal ownership, admission, testing, review and merge gates. Their benefits must be measured after actual adoption through reduced requirement omissions, lower repeated-read volume and fewer context-reconstruction corrections; task filing or merge alone establishes none of those outcomes.

## Self improvement should reuse the existing evidence loop

Conductor's changelog says its team uses routines to find system-prompt papercuts. That is a credible inspiration for making development events feed improvement proposals, but the inspected material supplies no controlled evidence that the routines autonomously improve coding performance. Remudero can pursue the stronger version: a repeated correction or failure becomes a sourced observation, then a deduplicated hypothesis, then a falsifiable candidate change, then a replayed and reviewed proposal. ([Conductor changelog](https://www.conductor.build/changelog/page/2))

The source and plan audit found existing work for recurring corrections, held-out prompt evaluation, and procedure signatures. W1-T11104, W1-T9639–W1-T9641, and the §4H/W1-T10727 path are the appropriate owners of that work. Filing another generic self-improvement engine would create competing authority and dilute the evidence. The new requirement and outcome contracts should instead improve the inputs available to those existing lanes. Missing evidence remains missing; a fluent retrospective does not become a rule, and a frequently observed failure class does not by itself establish one root cause. These task references describe existing plan ownership, not proof that every proposed mechanism has merged or is live. ([Strategy §4G/§4H](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/MASTER-PLAN.md), [Prompt evolution](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/src/lib/prompt-evolution.ts), [Procedure census](https://github.com/craigoley/remudero/blob/1438f25d780f8119342dbc36dc8715f9c6670e26/src/lib/procedure-census.ts))

A useful evaluation separates three questions. Did the candidate fix the specific observed defect, including a control that fails when the fix is removed? Does it preserve behavior on held-out cases rather than merely memorize the motivating example? After qualified adoption, does recurrence or operator intervention actually decline within a corpus the query demonstrably covers? Failed, canceled, interrupted and unknown runs must remain available for those comparisons. No new schedule, paid experiment, resource increase, model-routing change or automatic rule promotion follows from this research. Existing dispatch holds, including W1-T11104, remain unchanged.

## Conclusion

The durable advantage available to Remudero is a clearer chain of evidence across the whole task, not a larger collection of agent surfaces. Conductor contributes lessons about supervision and integration; Dex contributes lessons about concise task context and useful results. Remudero can combine those ideas with its stricter ownership and qualification model so that a source requirement, delegated action, verification receipt and later learning proposal remain traceable to one another.

The next proof is operational: implement the three bounded contracts through the normal protected flow, then test whether actual users and agents need less reconstruction and fewer corrections. The research and three filed tasks are planning artifacts. Implementation, hosted assurance, production adoption and measurable improvement remain separate outcomes to establish.
