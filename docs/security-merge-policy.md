# Exact-head high/critical merge protection

This is a staged, trusted metadata producer, not a claim that repository protection
has been activated. Source merge, producer adoption, smoke qualification and GitHub
enforcement are distinct boundaries. The operator approved the high/critical policy.

The Actions-produced status is ADVISORY: other PR workflows share the same Actions
App identity and may have check-write permission. Do not mistake that app binding
for a separately trusted security authority. Enforcement must use the existing
operator-controlled App/native protection after qualification; do not copy its
private key into a PR runner or create infrastructure to solve this.

Normal source effectors check the same trusted metadata program before arm,
re-arm, direct REST fallback, worker merge and enqueue; writes bind the verified
head with REST `sha` or CLI `--match-head-commit`. Other repositories are untouched.
This source guard is not adopted merely because a private test passes. Durable
UNKNOWN escalation and server enforcement remain mandatory before declaring done.

Core merge callers require the exact canonical URL
`https://github.com/craigoley/remudero/pull/<positive integer>`. Case changes,
encoded path components, alternate schemes/hosts, credentials, whitespace and
query/fragment suffixes must not make a core target look like another repository
and bypass admission. Recognizable core aliases and unresolved CLI number/branch
selectors return `unknown: noncanonical-pr-target` before metadata or merge writes.
Use the canonical URL returned by GitHub; do not retry through an alias or omit
`--match-head-commit`. Valid URLs for other repositories remain outside this
core-only policy. This boundary does not qualify historical repository redirects
or replace the server-side protection and bypass audit below.

The producer runs only main's script. It executes no PR source or artifacts, installs
no dependencies, calls no models, and creates no infrastructure. It checks complete
changed-file/check corpora, rename predecessors, trusted GitHub Advanced Security
identity, check generations, PR identity and a stable head/base before publication.
Only positively verified ignored paths can skip CodeQL. Unknown API/format/corpus
results publish an actionable `error`, not success or indefinite pending. CodeQL
events retry without a recurring PR monitor or a runner polling loop.

Merge groups currently publish explicit UNKNOWN: native code-scanning rulesets do
not cover them. Do not require this context on a queue branch until group evidence
has been independently qualified. Low/medium and quality-only output grammar has
unit coverage; its actual hosted shape still needs smoke qualification.

Activation checklist:

1. Verify trusted main execution and positive source, docs-only, rename, fork and
   Dependabot cases, including unavailable/spoofed/high controls.
2. Inspect current traditional protection AND rulesets/queue configuration.
3. Bind the required context to the intended GitHub App; retain every existing check
   and non-strict setting. Backfill exact open heads before requiring the producer.
4. Cover arm, re-arm, direct fallback and queue boundaries, including already armed
   PRs and privileged bypasses. Do not claim enforcement merely because a status exists.
5. Verify main's repaired alert closure separately from inherited security debt.

No runtime restart, scheduler activation, serving change or model pilot is authorized
by this producer. Unsupported evidence must remain visible until repaired or ruled on.
